## 3. 가장 중요한 반복 실패 (하나)

✅ **H1 — 640 입력에서 32px 미만으로 작아지는 이물(주로 플라스틱)을 반복적으로 놓친다.** (10/15 회의 확정)

- 못 찾음: 놓친 정답 159개 중 153개가 작은 객체
- 찾았지만 종류를 틀림: 상위 10장 Class 혼동 7개 (플라스틱 → 벌레 · 갈변 · 나뭇잎) · 모두 작은 조각
- 찾았지만 위치가 몇 px 어긋남: 상위 10장 위치 어긋남 8개 (IoU 0.15~0.45) · 640에서 5~10px 조각은 1~2px만 어긋나도 IoU 0.5 미만
- H2 · H3 일부(근처 작은 이물을 branch로 혼동 11개)도 같은 뿌리

## 4. 원인 가설

- 4K 원본을 긴 변 640(약 1/6)으로 줄이면 45~95px 조각이 8~16px 점이 되어 형태 · 색 정보가 거의 남지 않는다.
- 학습량 부족은 아니다: 학습곡선이 30~40 epoch에서 이미 천장 (Val mAP50 0.600 → 0.621 → 0.578) · 40 이후 val loss 반등.
- 그래서 입력 해상도를 올리면 FN(특히 작은 객체)이 줄 것이다.

## 5. 개선 실험 단계 변경 변수 (하나)

✅ **`imgsz` (입력 크기)** — 640 → **1280** 을 1순위로 시험 (10/15 회의 확정)

- 결정 규칙: `14_train_experiment.py --smoke` (1280 · batch 16 · 1 epoch) 결과 **GPU 메모리 최대 11GB 미만 → 1280** · 11GB 이상이거나 메모리 부족(OOM)으로 멈추면 → **960**
- batch 등 다른 설정은 바꾸지 않는다 (메모리 때문에 batch 를 줄이는 대신 imgsz 를 960 으로 낮춤 → 한 변수 원칙 유지)
- 최종 값 · 시험 결과는 `reports/improvement_experiment.md` 1 · 4장에 기록
