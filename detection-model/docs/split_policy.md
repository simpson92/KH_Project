## 3. 왜 기존 train / validation을 그대로 쓰지 않는가 (근거)

- 기존 validation 180장 **전부**가 train과 같은 5분 촬영 세션에 있음 (`val_in_mixed_groups = 180`)
- validation 중 60초 안에 train 사진이 있는 장: **135 / 180 (75%)**, 가장 가까운 차이 **8초**
- 촬영 시각 확인: EXIF 없음. 250410 첫 3장(약 45초 간격)을 직접 확인한 결과, 같은 트레이·조명·카메라 각도에서 배추 배치만 바꿔 연속 촬영함 → 파일명 = 촬영 순서로 판단
- 동일 이미지 확인: 900장 md5 비교 → 내용이 같은 이미지 0쌍 (파일명만 다른 동일 이미지 없음 · 2026-10-12)
- → 그대로 쓰면 **외운 장면으로 시험**을 보게 되어 점수가 부풀 수 있음 (Data Leakage)

## 4. Split 단위: capture_group (5분)

| 기준 | 세션 수 | 가장 큰 세션 | 1장짜리 세션 |
|---|---:|---:|---:|
| 1분 | 106 | 132 | 29 |
| **5분 (채택)** | **18** | 150 | 1 |
| 10분 | 13 | 150 | 0 |

- 결정: ✅ **5분**
- 근거: 1분은 같은 세션이 여러 묶음으로 갈라짐. 10분은 5분과 묶음 수 차이가 5개뿐 → 5분이 실제 촬영 휴식 구간에 가까움. 날짜 단위(4개)는 역할 4개에 나누기에 너무 적음.
- 경계 정의: 촬영 시각 순으로 정렬 후, 앞 사진과의 차이가 **5분 초과**이면 새 세션 (마이크로초까지 계산)
- 원칙: **한 세션은 한 역할에만** 들어간다. 예외는 6장 E1 하나뿐이다.

## 6. 특수 경우 처리

### 6.1 object_only 150장 (G18) → 전부 Train

- 사실: 250513 01:41~02:24 연속 촬영, 중간 간격 약 11초. 1분 기준으로 잘라도 132장이 한 덩어리.
- 결정: ✅ **A. 전부 Train**
- 근거: 나누면 몇 초 차이 사진이 Train과 평가 데이터에 동시에 들어감. 우리 목적은 김치 속 이물질 검출이므로 평가는 김치 장면으로 한다.
- 결과: Val · Frozen Test · Bridge에는 object_only가 없다 → 9장 한계에 기록.

### 6.2 Class 6(파·고추)은 사실상 G01 한 세션에만 있음 → 예외 E1

- 사실: Class 6 BBox 252개 중 **251개가 G01**(250410 14:44~15:28, 50장)에 있고, 나머지 1개는 G06에 있다. G01의 50장은 모두 장당 파·고추 4~6개가 있는 사진이다.
- 문제: 5분 세션 원칙대로면 G01이 통째로 한 역할에 들어간다.
  - G01 → Train: Frozen Test · Bridge에 Class 6이 0~1개 → **파·고추 성능 평가 불가**
  - G01 → Test 또는 Bridge: Train에 Class 6이 1개 → **파·고추 학습 불가**
  - → 회의 결정 "Test · Bridge에 Class별 20개 이상"을 지킬 방법이 없다.
- **예외 E1**: G01만 **2분 이상 쉰 지점**에서 하위 세션으로 나눠 배정한다.

| G01 하위 세션 | 시각 | 이미지 | Class 6 | 앞 하위 세션과 간격 | 배정 |
|---|---|---:|---:|---:|---|
| S1 | 14:44:03 ~ 14:45:32 | 3 | 15 | — | Frozen Test |
| S2 | 14:48:34 | 1 | 5 | 183초 | Frozen Test |
| S3 | 14:50:37 ~ 14:55:22 | 5 | 24 | 123초 | Bridge Holdout |
| S4 | 14:58:04 | 1 | 5 | 162초 | Val |
| S5 | 15:00:40 ~ 15:28:02 | 40 | 202 | 156초 | Train |

- Frozen Test 쪽(S1 · S2)과 가장 가까운 Train 사진(S5 시작)의 차이는 **약 12분**이라 5분 기준도 만족한다.
- 한계: 같은 날, 같은 트레이, 같은 파·고추 조각을 다시 흩뜨려 찍은 사진이라 **Class 6 점수는 다른 Class보다 좋게 나올 수 있다.** 보고서에는 "Class 6은 동일 촬영 세션 내 분할 결과(참고값)"로 표기한다.
- 대안 (E1을 쓰지 않는 경우): G01 전체를 Train에 넣고, Class 6은 최소 개수 기준에서 빼고 "평가 불가"로 기록한다.

### 6.3 그 밖의 경우

| 경우 | 사실 | 결정 |
|---|---|---|
| 1장짜리 세션 G02 | 250410 15:50:09 · 앞뒤 5분 이상 떨어짐 | 다른 세션과 똑같이 취급 |
| Class 3(벌레) 378개 | G16 173개, G18 89개에 몰림 · 나머지 세션은 20개 미만 | 평가 역할은 작은 세션 여러 개로 20개 이상 확보 |
| 정상 김치(Negative) 0장 | 라벨 검수 단계에서 수집 안 됨 | 정상 김치 오탐(FP)은 평가 불가 → 9장 한계 |

## 7. 합격 기준 (Split 결과 검증)

Split 결과는 아래를 **모두** 만족해야 확정한다. 하나라도 FAIL이면 배정을 다시 한다. `scripts/05_make_split.py`가 자동으로 검사한다.

| # | 기준 | 합격 조건 |
|---|---|---|
| 1 | 누락 · 중복 | 900장이 정확히 한 역할에만 들어감 (합계 900, 중복 0) |
| 2 | Leakage | 한 5분 세션이 두 역할에 걸치는 경우 0건 (예외 E1 제외) |
| 3 | 수량 | 역할별 이미지 수가 5장 허용 범위 안 |
| 4 | Class 최소 개수 | Frozen Test · Bridge Holdout에 Class 0 · 1 · 2 · 3 · 5 · 6이 각각 **20개 이상** |
| 5 | 장면 · 날짜 | Val · Frozen Test · Bridge는 김치 장면만, 각각 **2개 날짜 이상**의 세션으로 구성 |
| 6 | 재현성 | 같은 입력으로 다시 실행하면 같은 결과 |
| 7 | 학습 충분성 (추가) | Train에 Class 0 · 1 · 2 · 3 · 5 · 6이 각각 **100개 이상** |
| 8 | Val 포함 (추가 · 권장) | Val에 Class 0 · 1 · 2 · 3 · 5 · 6이 각각 **1개 이상** |

## 8. 배정 방법

- 방법: **스크립트 전수 탐색** (`scripts/05_make_split.py`). 무작위(seed)를 쓰지 않는다.
  - 세션 수가 18개뿐이라 가능한 조합을 전부 검사할 수 있다.
  - 7장 합격 기준을 모두 통과한 조합 중에서 아래 순서로 1개를 고른다.
    1. 목표 수량(600 / 75 / 75 / 150)과의 차이가 가장 작은 것
    2. Frozen Test · Bridge의 Class별 최소 개수가 가장 큰 것
    3. 그래도 같으면 세션 이름 순서가 앞선 것
  - 같은 입력이면 항상 같은 결과가 나온다 (재현성).

## 9. 알려진 한계

- 정상 김치(Negative) 0장 → 정상 김치 오탐률은 평가할 수 없다.
- object_only 150장은 한 세션이라 전부 Train에 배정 → "이물질만 있는 장면" 성능은 평가하지 않는다.
- Class 6(파·고추)은 한 세션(G01)에만 있어 예외 E1로 나눔 → Class 6 점수는 참고값이다.
- Frozen Test 75장은 작아서 점수가 조금만 달라져도 크게 흔들릴 수 있다.
- 촬영 날짜 4일 · 같은 트레이 · 같은 조명 → 다른 환경에서의 성능은 이 데이터로 알 수 없다.
